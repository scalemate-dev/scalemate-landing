## Note: tooling bug found (out of scope, filed for awareness)

`scripts/gsc/gsc_client.py` `main()` passes the `--raw` JSON body straight into `GSCClient.query(**body)`, which expects **snake_case** kwargs (`row_limit`, `start_date`, `end_date`), while `capabilities/gsc.md`'s own documented example (`{"dimensions":["query","page"],"rowLimit":1000}`) uses **camelCase**. Following the docs verbatim throws `TypeError: unexpected keyword argument 'rowLimit'`. Worked around by using snake_case keys directly in this run. Recommend either accepting both cases in `query()` or fixing the doc example — did not touch it here per "prove the pipe before wiring" / this being outside the analysis unit's write scope.
