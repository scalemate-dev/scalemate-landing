# Stage 5 — Output + Pipeline Update

## 5a. Save QA report

Зберегти QA result у `seo-system-v1/output/output/topics/[slug]/qa.md` за форматом нижче.

### PASS format

```markdown
## QA Result: PASS ✅

**Content-ops score:** [X/100]
**Copy-editing:** completed, [N] changes made
**Humanizer:** Low AI level ✅
**SEO Technical:** all checks passed ✅
**Skipped (skill unavailable):** [list якщо є]

Draft is production-ready.
File: [path to final draft]

**Next step:** Natalia final review (Checkpoint 4).
Present to her with: "Ready for publish. Read draft at [path]. Approve / Changes / Reject."
```

### FAIL format

```markdown
## QA Result: NEEDS WORK ⚠️

**Failed at stage:** [1/2/3/4]
**Content-ops score:** [X/100] (target 90)
**Top issues:**
1. [Specific issue + line/section reference]
2. [Specific issue]
3. [Specific issue]

**Action:** Return to content-creator. Revision notes saved at `output/topics/[slug]/revision-notes.md`.
```

## 5b. Save revision notes (FAIL only)

Якщо FAIL — зберегти конкретні fixable issues у `seo-system-v1/output/output/topics/[slug]/revision-notes.md`:

```markdown
# Revision Notes — [topic]

> Generated by QA on YYYY-MM-DD. content-creator читає цей файл при повторі і виправляє кожен item.

## Critical (must fix)

- [ ] [line 45] Замінити `In today's fast-paced world` на конкретний приклад або видалити speech opener
- [ ] [section "How it works"] Додати first-hand experience marker — currently 0 markers (потрібен min 1)
- [ ] [meta description] 178 chars — скоротити до 150-160

## Improvements (nice-to-have)

- [ ] ...
```

content-creator при повторі читає `revision-notes.md` і фіксить кожен item.

## 5c. Pipeline update

Оновити [`workflow/pipeline.md`](../../workflow/pipeline.md):

### PASS

`6. Approved for QA` → `7. Pending Natalia deploy`

```
- topic-slug
  ...
  artifact: output/topics/[slug]/draft.md
  qa-passed: YYYY-MM-DD
```

### FAIL — повторна ітерація

`6. Approved for QA` → `4. Approved for writing` (для content-creator)

```
- topic-slug
  ...
  qa-failed: YYYY-MM-DD
  qa-failed-stage: [1/2/3/4]
  revision-notes: output/topics/[slug]/revision-notes.md
```

### FAIL — повне відкидання

`6. Approved for QA` → `9. Rejected / Archived` (тільки якщо topic непотрібен взагалі — рідко)

```
- topic-slug
  ...
  qa-failed: YYYY-MM-DD
  rejected-reason: [explanation]
```
